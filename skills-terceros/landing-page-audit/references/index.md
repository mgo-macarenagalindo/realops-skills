# Reference index

Condensed, rule-only extraction of *Refactoring UI* by Adam Wathan & Steve Schoger. Each file is a scannable checklist of actionable rules for use as input to a UI review skill.

## Files

- [process.md](process.md) — design process, starting points, constraints
- [hierarchy.md](hierarchy.md) — visual hierarchy, emphasis, de-emphasis
- [spacing.md](spacing.md) — whitespace, layout, sizing systems, grids
- [typography.md](typography.md) — type scale, fonts, alignment, line-height, letter-spacing
- [color.md](color.md) — HSL, palette construction, accessibility
- [depth.md](depth.md) — shadows, light source, elevation, layering
- [images.md](images.md) — photo quality, contrast over images, scaling, user content
- [polish.md](polish.md) — finishing touches, accents, empty states, breaking conventions

Landing-page-specific checks (first screen, CTAs, proof, section rhythm, mobile) are in [landing-page.md](landing-page.md).

## How to use as review input

Each rule is phrased as either an instruction ("Do X") or a check ("If X, then Y"). When reviewing a UI, walk each file and flag any violation. Most rules have a stated reason — preserve the reason when reporting issues so feedback is actionable, not dogmatic.
