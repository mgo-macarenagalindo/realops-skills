# Casos de uso · De SOP a Skill

Tres situaciones de infonegocio donde un proceso escrito pasa a correr solo. Negocios y nombres ficticios.

---

## 1. El SOP de handoff de venta a servicio

**La situación.** En un programa high ticket de nutrición deportiva, el closer le pasa al equipo de servicio un resumen de cada venta. Hay un SOP en Notion, pero cada closer lo escribe distinto y el equipo de servicio siempre tiene que volver a preguntar.

**Qué le pasás.** El SOP pegado, las frases con las que se pide ("armá el handoff de la venta de hoy") y un handoff bien hecho (anonimizado).

**Qué te devuelve.** La carpeta `handoff-venta-servicio/` con el `SKILL.md` (preguntas al closer, pasos, validación de que estén los 6 datos obligatorios, la frase exacta si falta uno), los casos de uso, el ejemplo y las 4 pruebas.

**Por qué sirve.** El SOP deja de depender de que cada closer se acuerde. Es la actividad T3 del programa hecha sobre un proceso real.

## 2. Una skill que escribe en la base

**La situación.** En una membresía de fotografía, cada mes alguien marca a mano en Airtable quién renovó y quién no, y una vez se marcaron como activas personas que no habían pagado.

**Qué le pasás.** El proceso contado en voz alta y el error que pasó.

**Qué te devuelve.** El veredicto (es material de skill y **lleva regla de oro** porque escribe en la base), los pasos en el orden preparar · prueba en seco · validaciones · escribir solo con OK · verificar · avisar, y la validación nueva que nace del error ("comprobante no es pago: solo cuenta lo conciliado").

**Por qué sirve.** Cuando una skill toca datos, la diferencia entre una herramienta y un riesgo es la regla de oro escrita.

## 3. La skill que Claude no usa

**La situación.** Armaste una skill para el reporte del lunes, la subiste, pero cuando pedís "pasame los números de la semana" Claude responde sin usarla.

**Qué le pasás.** El `SKILL.md` actual y tres frases con las que lo pedís de verdad.

**Qué te devuelve.** El diagnóstico (la description dice "reporte operativo semanal" y vos decís "números de la semana", "cómo cerró la semana"), la description reescrita con tus palabras, y los 4 pedidos de prueba para confirmar el arreglo.

**Por qué sirve.** La mayoría de las skills que "no andan" tienen la description mal escrita. Se arregla en cinco minutos.
